   웹 문서는 안전사용·중독·응급처치 같은 비정형 지식(벡터 검색)용으로 나눈다.


────────────────────────────────────────
2. 과제 목표
────────────────────────────────────────

정형 농약제품 데이터와 비정형 안전사용 웹 문서를 하나의 상담 시스템에 결합하고,
단원에서 배운 네 가지 검색 패러다임을 같은 코퍼스·같은 질문으로 비교한다.

학습 포인트
  1) 벡터 유사도만으로는 답하기 어려운 멀티홉 관계 질문에서 Graph RAG의 이점을 확인한다.
  2) 질문 유형(인사 / 단일 사실 / 관계 추적 / 안전 수칙)에 따라 Agent가 도구를 스스로 고르는지 확인한다.
  3) 검색 결과를 LLM이 채점하고, 부족하면 질의 재작성·외부(웹) 문서로 전환하는 CRAG 루프를 구현한다.
  4) 여러 질의 변형과 dense/sparse 검색을 RRF로 융합하는 RAG Fusion을 구현한다.


────────────────────────────────────────
3. 과제 내용
────────────────────────────────────────

[1] 데이터 준비

  - OpenAI API 키는 C:\env\.env 에서 불러온다. 키 값은 출력하지 않는다.
  - 엑셀을 로드하고 작물명에 다음 키워드가 포함된 행만 남긴 뒤,
    작물별로 상표명을 최대 25개씩 샘플링한다. (재현을 위해 random_state 고정)
      고추, 벼, 토마토, 사과, 배추
  - 샘플링된 각 행을 사실 문장(fact)으로 변환한다. 예:
      "상표명 '가드너'는 작물 '고추'의 '탄저병'에 사용하는 살균제이며,
       주성분은 Azoxystrobin+Difenoconazole이고 인축독성은 Ⅳ급(저독성)이다.
       제조사는 (주)동방아그로, 안전사용시기는 수확3일전이다."
  - 웹 문서 주소 파일에서 URL을 파싱해 페이지를 수집하고, 본문을 청킹한다.
  - 제품 사실 문장과 안전사용 웹 청크를 구분해 벡터스토어를 만든다.
    (제품 KB / 안전사용 웹 / 통합 중 필요한 조합을 사용)
  - 임베딩·생성 모델은 자유롭게 선택하되, 전략 비교 시에는 동일하게 고정한다.
    (예시: text-embedding-3-small, gpt-4o-mini)


[2] Graph RAG — 관계형 검색

  참고: 01_Graph RAG - 관계형 검색 원리.ipynb

  - 엑셀 컬럼에서 (주체, 관계, 객체) 트리플을 규칙 기반으로 추출한다.
    LLM 추출을 전 행에 돌리지 않는다. (행 수가 많아 비용·시간이 큼)
    관계 어휘 예:
      USED_ON, CONTROLS, CONTAINS, MANUFACTURED_BY,
      HAS_TOXICITY, HAS_FISH_TOXICITY, HAS_USE, HAS_PHI, HAS_FORMULATION
  - NetworkX MultiDiGraph로 저장한다. (노드=개체, 엣지=관계)
  - 질문에서 seed 개체를 찾고, 양방향 k홉 순회로 서브그래프를 수집한다.
  - 동일 질문에 대해 Naive Vector RAG와 Graph RAG 답을 비교한다.
    반드시 포함할 질문 유형:
      · 멀티홉 관계 질문 (예: 작물+병해충 → 제품 → 회사/독성/안전사용시기)
      · 단일 사실 질문 (예: 특정 상표명의 주성분)


[3] Agentic RAG — 검색 전략 자율 결정

  참고: 02_Agentic RAG - Agent가 검색 전략 자율 결정.ipynb

  - 다음 도구를 LangChain @tool 로 정의하고 LangGraph ReAct 루프로 연결한다.
      (1) vector_search  : 제품 사실 문장 의미 검색 (단일 사실 조회)
      (2) graph_search   : 개체 기점 그래프 순회 (멀티홉 관계)
      (3) safety_search  : 안전사용 웹 문서 검색 (중독·응급처치·주의사항)
  - Agent가 도구 선택·호출 횟수·종료 시점을 스스로 판단하게 한다.
  - 도구 호출 트레이스를 출력한다.
  - 최소 아래 질문 유형을 실험한다.
      · 검색이 필요 없는 인사
      · 제품 단일 사실
      · 멀티홉 관계
      · 농약 중독/응급처치/사용 후 관리 (웹 문서)


[4] Self-Corrective RAG — 검색 결과 자기평가·재시도

  참고: 03_Self-Corrective RAG - 검색 결과 자기평가·재시도.ipynb

  - 제품 KB를 내부 지식베이스, 안전사용 웹 문서를 외부(웹) 지식으로 둔다.
  - LangGraph로 다음 루프를 구현한다.
      retrieve → grade_documents → (관련 있음) generate
                                 → (관련 없음, 재시도 남음) transform_query → retrieve
                                 → (재시도 소진) web_search → generate
  - 문서 채점은 yes/no structured output, 질의 재작성은 구어체·오탈자 교정.
  - 재시도 한도를 두고, 근거가 없으면 모른다고 답한다.
  - 최소 아래 질문 유형을 실험한다.
      · 제품 KB에서 바로 잡히는 정상 질문
      · 구어체·오탈자가 있는 질문 (재작성 유도)
      · 제품 KB에는 없고 안전사용 웹 문서에만 있는 질문 (웹 전환)


[5] RAG Fusion — 앙상블 검색 통합

  참고: 04_RAG Fusion - 앙상블 검색 통합 기법.ipynb

  - 원래 질문을 여러 하위 질의로 재작성한 뒤, 질의별 벡터 검색 순위 리스트를 만든다.
  - Reciprocal Rank Fusion(RRF, k=60)으로 하나의 순위표로 융합한다.
  - 추가로 벡터(dense) + BM25(sparse) 하이브리드를 RRF(또는 EnsembleRetriever)로 구현한다.
  - Naive RAG / Multi-Query Fusion / Hybrid Ensemble 답을 같은 질문으로 비교한다.


[6] 종합 비교

  동일한 질문 집합에 대해 다음을 표로 정리한다.

  - 사용한 전략 (Naive / Graph / Agentic / CRAG / Fusion)
  - 검색에 쓰인 근거 유형 (제품 사실 / 그래프 트리플 / 웹 문서)
  - 답변 품질 (정성 평가)
  - 소요시간
  - 상황별 추천 전략과 선택 이유

4. 구현 조건 / 제약
────────────────────────────────────────

  - API 키: C:\env\.env 의 OPENAI_API_KEY 만 사용. 키 값 출력 금지.
  - 엑셀 전체(약 14만 행)를 임베딩하거나, 전 행에 대해 LLM 트리플 추출을 돌리지 않는다.
  - 답변은 검색된 문맥(사실 문장, 그래프 트리플, 웹 청크)에만 근거하는 grounded 프롬프트를 사용한다.
    근거가 없으면 "주어진 자료만으로는 알 수 없다"고 답한다.
  - 벡터스토어는 FAISS 권장 (단원 예제와 동일). Chroma를 써도 되나 Windows 한글 경로 이슈에 주의한다.
  - Graph RAG의 그래프 구축은 엑셀 컬럼 기반 규칙 추출을 기본으로 한다.
    웹 문서에서 LLM 트리플 추출을 추가하는 것은 선택(가산).
  - 단원 예제 노트북(01~04)의 구현 패턴(도구 docstring, k홉 순회, CRAG 상태머신, RRF 수식)을 따른다.
