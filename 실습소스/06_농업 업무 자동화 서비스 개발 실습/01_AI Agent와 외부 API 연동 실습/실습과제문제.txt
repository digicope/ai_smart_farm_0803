====================================================================
실습과제: AI Agent와 외부 API 연동 — 기상청 예보 + 작물 재배 길잡이
====================================================================

교과목: 농업 업무 자동화 서비스 개발 실습
단원: 01_AI Agent와 외부 API 연동 실습
권장 파일명: AI_Agent와_외부_API_연동_실습_답안.ipynb


■ 배경
--------------------------------------------------------------------
01번 예제(`01_기상청_단기예보_중기예보_API_호출_예제.ipynb`)에서는
공공데이터포털의 기상청 단기예보·중기예보 API를 Python으로 호출하고
표로 정리했다.

이번 과제에서는 그 호출을 **AI Agent의 Tool**로 감싸고,
같은 폴더의 **농촌진흥청 농업기술길잡이 PDF**를 검색 도구로 연결한다.

목표 흐름은 발급방법 요약 문서와 같다.

    사용자: "앞으로 10일간 날씨를 분석해서 토마토 농작업 계획을 세워줘."
                    │
                    ▼
               AI Agent
        ┌───────────┴───────────┐
        ▼                       ▼
  단기예보 Tool            중기예보 Tool
  (1~3일 상세)             (최대 11일 전망)
        └───────────┬───────────┘
                    ▼
            작물 길잡이 검색 Tool  (PDF RAG)
                    ▼
              LLM 종합 분석
                    ▼
              농업 의사결정 조언

날씨(실시간 외부 API)와 재배 지식(로컬 PDF)을 섞어 답하되,
없는 내용은 지어내지 않는 Agent를 만드는 것이 핵심이다.


■ 학습 목표
--------------------------------------------------------------------
- 외부 API를 LangChain `@tool`로 감싸 Agent가 필요할 때만 호출하게 한다.
- 단기예보 키와 중기예보 키를 분리하고, 질문의 시간 범위에 따라
  적절한 Tool만(또는 둘 다) 선택하게 한다.
- 격자(nx, ny)와 중기 구역코드(regId)의 차이를 이해하고 올바르게 사용한다.
- 작물 재배 PDF를 청킹·임베딩해 검색 Tool로 연결한다.
- 날씨 API 결과와 PDF 근거를 함께 사용해 농작업 조언을 만든다.
- 근거가 없는 작물/내용은 "주어진 자료만으로는 알 수 없다"고 답한다.


■ 사전 준비
--------------------------------------------------------------------
1. C:\env\.env 에 다음 키가 있어야 한다.

       KMA_SHORT_TERM_KEY=단기예보_API_인증키
       KMA_MID_TERM_KEY=중기예보_API_인증키
       OPENAI_API_KEY=OpenAI_API_키

   (기상청 키 발급은 같은 폴더 `기상청_단기예보_중기예보_API_발급방법_요약.md` 참고)
   두 기상청 API는 별도 서비스이므로 키를 섞어 쓰지 않는다.

2. 01번 예제 노트북을 먼저 실행해 단기·중기 API가 정상 동작하는지 확인한다.

3. 권장 패키지:
       requests, pandas, python-dotenv, pypdf,
       langchain-core, langchain-openai, langchain-community,
       langgraph, faiss-cpu (또는 동등한 벡터스토어)

4. API 키는 코드/노트북/출력에 절대 노출하지 않는다.

■ 요구사항 (단계별로 구현할 것)
--------------------------------------------------------------------

[STEP 0] 환경 준비
  - C:\env\.env 에서 KMA_SHORT_TERM_KEY, KMA_MID_TERM_KEY,
    OPENAI_API_KEY 를 로드한다.
  - 키가 없으면 예외를 발생시키고, 키 값은 출력하지 않는다.
  - LLM은 예: ChatOpenAI(model="gpt-4o-mini", temperature=0)
  - 임베딩은 예: OpenAIEmbeddings(model="text-embedding-3-small")


[STEP 1] 조회 지점 확정
  - 실습용 농업 지역 1곳을 정한다. (예: 전주, 수원, 나주 등)
  - 단기예보용 격자 nx, ny 는
    `기상청41_..._격자_위경도(2607).xlsx` 에서 찾는다.
  - 중기육상예보 regId, 중기기온예보 regId 는
    `중기예보_중기기온예보구역코드_2025.12.xlsx` 및 중기예보 가이드에서
    찾는다.
  - 선택한 지역명, nx, ny, 육상 regId, 기온 regId 를 노트북에 표로 남긴다.
    (서울 종로 예제 좌표를 그대로 복사만 하면 감점)


[STEP 2] 단기예보 Tool
  - 01번 예제의 getUltraSrtNcst / getVilageFcst 호출을 재사용한다.
  - LangChain `@tool` 로 감싼다. 예:
        get_short_term_weather(nx: int, ny: int)
  - KMA_SHORT_TERM_KEY 만 사용한다.
  - base_date / base_time 은 현재 시각(Asia/Seoul) 기준으로 자동 계산한다.
  - Agent가 읽기 쉽게 기온, 강수확률, 하늘상태, 강수형태, 습도 등을
    요약 문자열 또는 JSON으로 반환한다.
  - 인증키 이중 인코딩, JSON이 아닌 응답, resultCode != 00 을 처리한다.


[STEP 3] 중기예보 Tool
  - 01번 예제의 getMidFcst / getMidLandFcst / getMidTa 를 재사용한다.
  - LangChain `@tool` 로 감싼다. 예:
        get_mid_term_weather(land_reg_id: str, ta_reg_id: str)
  - KMA_MID_TERM_KEY 만 사용한다.
  - tmFc 는 06시/18시 중 최신 발표시각으로 자동 계산한다.
  - 육상(날씨·강수확률)과 기온(최저·최고)을 +3일~+10일 형태로 묶어 반환한다.
  - 육상 regId 와 기온 regId 가 다르다는 점을 Tool description에 명시한다.


[STEP 4] 작물 길잡이 검색 Tool (PDF RAG)
  - [B]의 PDF 6종을 모두 로드한다.
  - 청크 메타데이터에 최소 다음을 넣는다.
        crop (토마토/고추/수박/참외/고구마/사과),
        source (파일명), page
  - 파일명으로 crop 을 매핑한다. (예: 파일명에 "토마토" → crop="토마토")
  - RecursiveCharacterTextSplitter 등으로 청킹한다.
    (권장: chunk_size 800~1000, overlap 100~150)
  - 벡터스토어를 만들고 persist 한다. (재실행 시 재임베딩하지 않기)
  - LangChain `@tool` 로 감싼다. 예:
        search_crop_guide(query: str, crop: str)
    crop 이 주어지면 해당 작물 청크만 검색한다.
  - 검색 결과에는 작물명, 파일명, 페이지, 발췌문을 포함한다.
  - 검색된 문맥에 없는 내용은 만들어 내지 않도록 description/프롬프트를 적는다.


[STEP 5] Agent 구성
  - 위 3개 Tool을 장착한 Agent(LangGraph 또는 동등한 create_agent)를 만든다.
  - 시스템 프롬프트에 다음을 분명히 넣는다.
      · 1~3일 상세 날씨 → 단기예보 Tool
      · 4일 이후~10일 전망, "앞으로 일주일/10일" → 중기예보 Tool
      · 10일 계획처럼 단기+중기가 모두 필요하면 둘 다 호출
      · 재배/병해충/정식/시비/수확 등 작물 지식 → PDF 검색 Tool
      · 날씨는 API 결과만, 재배법은 PDF 발췌만 근거로 답한다
      · PDF에 없는 작물(예: 딸기, 벼)은 자료 부족을 명시한다
      · 키/좌표/구역코드를 사용자에게 출력하지 않는다
  - 도구 호출 과정(어떤 Tool을 왜 호출했는지)이 노트북에 보이도록 한다.


[STEP 6] 실행 시나리오 (최소 5개, 모두 실제 실행)
  아래 질문을 같은 Agent로 실행하고, 호출된 Tool 목록과 최종 답을 남긴다.

  (A) 단기만
      "오늘과 내일 {선택한 지역} 날씨를 알려줘.
       강수 가능성이 있으면 방제도 함께 주의해야 하는지 짧게 말해줘."
      → 단기예보 Tool 호출. PDF는 선택(작물이 명시되지 않으면 호출하지 않는 것이 바람직).

  (B) 중기만
      "앞으로 10일간 {선택한 지역} 날씨 전망과 기온을 정리해줘."
      → 중기예보 Tool 호출. (상세가 필요하면 단기도 추가 호출 가능)

  (C) PDF만
      "토마토 육묘와 정식 시 주의사항을 농업기술길잡이 기준으로 요약해줘."
      → search_crop_guide 만 호출. 날씨 API를 호출하지 않아야 한다.

  (D) API + PDF 결합 (핵심 시나리오)
      "앞으로 10일간 {선택한 지역} 날씨를 분석해서 토마토 농작업 계획을 세워줘."
      → 단기 Tool + 중기 Tool + 토마토 PDF 검색이 모두 사용되어야 한다.
      → 답변에 실제 예보 수치(기온/강수확률 등)와 PDF 근거(파일명·페이지)가
        함께 들어가야 한다.

  (E) 자료 없음 / 잘못된 라우팅 방지
      "딸기 재배에서 정식 후 물 관리 방법을 알려줘."
      → PDF에 딸기가 없으므로 날씨를 지어내거나 다른 작물 내용을
        딸기인 것처럼 답하면 안 된다. 자료 부족을 명시한다.


[STEP 7] 결과 정리
  - 시나리오 A~E에 대해 표를 만든다.
        질문 | 기대한 Tool | 실제 호출 Tool | 날씨 근거 여부 | PDF 근거 여부 | 비고
  - (D)의 최종 조언을 농작업 일정 형태로 보기 좋게 정리한다.
    (예: D+0~2 상세 작업, D+3~10 전망 작업)


■ 구현 조건 / 제약
--------------------------------------------------------------------
- 기상 더미 데이터나 임의의 숫자를 만들어 쓰지 않는다. 반드시 실API를 호출한다.
- 단기예보 키로 중기 API를 치거나, 중기 키로 단기 API를 치지 않는다.
- 단기예보는 위·경도가 아니라 격자 nx, ny 를 사용한다.
- 중기예보는 격자 좌표가 아니라 구역코드 regId / 지점번호 stnId 를 사용한다.
- PDF 답변은 검색된 청크에만 근거한다. 근거가 없으면 모른다고 답한다.
- Windows에서 Chroma persist 한글 경로 문제가 있으면 FAISS 등 대안을 사용한다.
- 01번 예제 노트북을 그대로 제출하면 안 된다. Agent + PDF 검색이 포함되어야 한다.
