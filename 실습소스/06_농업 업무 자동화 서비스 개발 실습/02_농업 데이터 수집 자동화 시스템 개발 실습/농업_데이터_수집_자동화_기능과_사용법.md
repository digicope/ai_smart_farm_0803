# 농업 데이터 수집 자동화 — 기능과 사용법

농촌진흥청·공공데이터포털 **파일데이터(CSV/ZIP)** 를 AI Agent가 직접 내려받고, SQLite 창고에 적재·조회·경보하는 실습 소스입니다.

Open API 인증키(`serviceKey`)는 쓰지 않습니다. 브라우저에서 파일을 미리 받아 둘 필요도 없습니다. Agent의 `download_portal_data` Tool이 `fileDownload.do`로 원문을 받습니다.

OpenAI 키만 `C:\env\.env`의 `OPENAI_API_KEY`를 사용합니다.

```text
사용자: "포털에서 CSV를 내려받고 창고에 적재해줘"
        │
        ▼
   create_agent
    목록 / 다운로드 / 적재 / 조회 / 경보
        │
        ▼
   공공데이터포털 fileDownload.do
        │
        ▼
   data/*.csv  →  C:\env\farm_warehouse\farm_warehouse.db
```

## 1. 구성 파일

| 파일 | 역할 |
|---|---|
| `farm_collect_core.py` | Agent, Tool 6개, SQLite 적재·조회·경보. 설정은 `COLLECTION_CONFIG` 상수 |
| `portal_csv.py` | 포털 파일 다운로드 + 실습용 CSV 정리 |
| `01_농업_데이터_수집_자동화_에이전트_예제.ipynb` | 예제 노트북 (STEP 0~시나리오 A~E) |
| `streamlit_app.py` | 같은 Agent의 Streamlit 화면 |
| `실습과제문제.txt` | 과제 요구사항 |
| `data/` | 다운로드 캐시. 없어도 되고, Tool이 다시 만듦 |

설정 JSON(`collection_config.json`)은 없습니다. 포털 URL·작목·경보 임계값은 `farm_collect_core.COLLECTION_CONFIG`에 있습니다.

## 3. 수집 대상 (COLLECTION_CONFIG)

| Agent source | 내용 | 연도 | 포털 | 정리 파일 |
|---|---|---|---|---|
| `weather` | 완주군 농업기상 일별 집계 (반교리·이서면) | 2023 | [15136768](https://www.data.go.kr/data/15136768/fileData.do) | `rda_weather_wanju_2023.csv` |
| `farm` | 노지 농가정보 (작목·품종·정식·수확량) | 2024 | [15126334](https://www.data.go.kr/data/15126334/fileData.do) | `rda_farm_info_2024.csv` |
| `growth` | 노지 생육. 고추는 전국, 밀·배추·양파·콩은 전북 | 2024 | 위와 동일 ZIP | `rda_growth_2024.csv` |
| `pest_sites` | 병해충 예찰 지점 | 2015–2024 | [15123424](https://www.data.go.kr/data/15123424/fileData.do) | `rda_pest_sites.csv` |
| `pest_info` | 병해충 목록 (NCPMS·PSIS) | 2025 | [15151253](https://www.data.go.kr/data/15151253/fileData.do) | `rda_pest_catalog.csv` |

- **있는 작목:** 고추, 마늘, 밀, 배추, 사과, 양파, 옥수수, 콩, 포도, 논벼
- **없는 작목:** 토마토, 딸기, 수박, 참외 — 다른 작물로 대체하지 않음

`farm`과 `growth`는 같은 ZIP을 받습니다. `source='farm'` 또는 `source='growth'` 어느 쪽이든 농가·생육 CSV를 함께 정리합니다.

## 4. 기능

### 4.1 `portal_csv.py` — 포털 다운로드와 CSV 정리

로그인 없이 파일데이터를 받습니다. Open API REST(`serviceKey`, `api.odcloud.kr`)는 쓰지 않습니다.

다운로드 순서:

1. 포털 상세 페이지에서 UDDI 추출
2. `selectFileDataDownload.do`로 `atchFileId` 획득
3. `fileDownload.do`로 CSV/ZIP 저장

주요 함수:

| 함수 | 설명 |
|---|---|
| `download_and_prepare(source, force=False)` | Agent가 쓰는 진입점. source별 다운로드 + 정리 |
| `download_raw(portal_id, force)` | 원본 CSV/ZIP 저장 |
| `prepare_weather` | 완주군만 남기고 일별 집계 (기온 min/max/mean, 습도, 강수 합) |
| `prepare_farm` | 2024 농가정보 컬럼명 영문 정리 |
| `prepare_growth` | 고추(전국) + 전북 밀/배추/양파/콩 |
| `prepare_pest_sites` / `prepare_pest_catalog` | 예찰 지점·병해충 목록 정리 |

기상 원본은 약 85MB입니다. `rda_weather_wanju_2023.csv`가 이미 있으면 재다운로드를 생략합니다. 다시 받으려면 `force=True`.

### 4.2 `farm_collect_core.py` — Agent와 창고

| 기능 | 설명 |
|---|---|
| `COLLECTION_CONFIG` | 포털 URL, 초점 지역(전북 완주), 작목, 경보 임계값 |
| `build_runtime()` | `ChatOpenAI(gpt-4o-mini)` + Tool 6개로 `create_agent` |
| `ask_agent(runtime, question)` | 질문 실행. 답변·호출 Tool·트레이스 반환 |
| `ingest_source` | CSV → SQLite (`if_exists="replace"`) |
| `query_table` | 시도·시군·작목·기간 필터, 최대 80건 |
| `detect_alerts` | 습도·강수·고온 임계값 + 농가 비고(병해·폭염) |

창고 테이블:

| 테이블 | 날짜 컬럼 | 비고 |
|---|---|---|
| `weather` | `obs_date` | 2023, 전북 완주 |
| `farm` | `plant_date` | 2024 농가 |
| `growth` | `survey_date` | 2024 생육 |
| `pest_sites` | `year` | 예찰 지점 |
| `pest_info` | — | 병해충명 검색 |
| `ingest_log` | `ingested_at` | 적재 시각·건수 |

### 4.3 Agent Tool 6개

| Tool | 언제 쓰나 |
|---|---|
| `list_data_sources()` | 수집 가능한 종류만 물을 때. 다운로드하지 않음 |
| `download_portal_data(source, force=False)` | “내려받아 / 수집해 / 포털에서 받아”. `source='all'`이면 전부 |
| `ingest_farm_data(source)` | 받은 CSV를 창고에 넣기. 파일이 없으면 먼저 download |
| `get_collection_status()` | 테이블별 건수·기간·적재 시각 |
| `query_collected_data(table, sido, sigungu, crop, start_date, end_date)` | 수치·명단 조회 |
| `detect_farm_alerts()` | 이상·점검·경보. 반드시 이 Tool을 호출 |

`query_collected_data` 참고:

- `table`: `weather`, `farm`, `growth`, `pest_sites`, `pest_info`
- 전북/완주/김제 등은 `sido`, `sigungu`
- 병해충명은 `table='pest_info'`, `crop` 자리에 병명 (예: 역병)
- **고추 생육은 전국 자료**입니다. 고추 조회에 `sido='전북'`을 넣으면 0건입니다. 기상만 완주로 필터하세요.

경보 임계값 (`COLLECTION_CONFIG["alert_thresholds"]`):

| 키 | 값 | 의미 |
|---|---|---|
| `humidity_high_pct` | 85 | 고습 |
| `rainfall_heavy_mm` | 20 | 강우 |
| `rainfall_sensor_outlier_mm` | 400 | 일합계가 비정상적으로 크면 센서 이상 |
| `tmax_hot_c` | 33 | 고온 |

이서면 등에서 강수 일합계가 매우 크게 나올 수 있습니다. 400mm 초과는 폭우가 아니라 원자료 시간값 합산 이상으로 처리합니다.

## 5. 사용법

### 5.1 예제 노트북 (권장)

`01_농업_데이터_수집_자동화_에이전트_예제.ipynb`를 위에서부터 실행합니다.

1. **STEP 0** — `OPENAI_API_KEY` 로드, 경로 확인
2. **STEP 1** — `load_config()`로 수집 대상 표. CSV가 없으면 “아직 없음”
3. **STEP 2~5** — `build_runtime()`으로 Agent 생성
4. **시나리오 A~E** — `ask_agent`로 질문

노트북 핵심:

```python
from farm_collect_core import build_runtime, ask_agent, SAMPLE_QUESTIONS

runtime = build_runtime()
out = ask_agent(runtime, SAMPLE_QUESTIONS[1]["text"])  # 시나리오 B
print(out["tools"])
print(out["answer"])
```

### 5.2 Streamlit 앱

노트북과 같은 `farm_collect_core` Agent를 웹으로 씁니다.

```text
cd "02_농업 데이터 수집 자동화 시스템 개발 실습"
streamlit run streamlit_app.py
```

- 시나리오 A~E 버튼으로 과제 질문을 바로 넣을 수 있습니다.
- 사이드바에 창고 건수·CSV 캐시·경보 임계값이 보입니다.
- 답변 아래 도구 호출 트레이스가 남습니다.
- 시나리오 B(전체 수집)는 포털 다운로드 때문에 시간이 걸릴 수 있습니다.

### 5.3 파이썬에서 Agent만 쓰기

실습 폴더에서:

```python
from farm_collect_core import build_runtime, ask_agent

runtime = build_runtime()
result = ask_agent(
    runtime,
    "공공데이터포털에서 농업 CSV를 내려받고 창고에 적재한 뒤 수집 현황을 보고해줘.",
)
print("호출 Tool:", " → ".join(result["tools"]))
print(result["answer"])
```

`ask_agent` 반환값:

- `answer`: Agent 최종 답변
- `tools`: 호출한 Tool 이름 목록
- `trace`: Tool 인자·결과 미리보기

### 5.3 Tool 없이 다운로드·적재만 (디버깅)

Agent를 거치지 않고 포털 수신과 SQLite 적재를 확인할 때:

```python
from portal_csv import download_and_prepare
from farm_collect_core import ingest_source, format_status

print(download_and_prepare("all", force=False))
print(ingest_source("all"))
print(format_status())
```

특정 출처만:

```python
download_and_prepare("weather")   # 완주 기상
download_and_prepare("farm")      # 농가+생육 (같은 ZIP)
download_and_prepare("pest_info")
```

### 5.4 설정 확인

```python
from farm_collect_core import load_config, format_sources

cfg = load_config()
print(cfg["sources"])
print(cfg["alert_thresholds"])
print(format_sources())
```

## 6. 시나리오 A~E (기대 동작)

| | 질문 요지 | 기대 Tool | 주의 |
|---|---|---|---|
| **A** | 수집할 수 있는 농업 데이터 종류 | `list_data_sources` | 다운로드하지 않는 것이 바람직 |
| **B** | 포털에서 내려받고 창고에 적재한 뒤 현황 | `download_portal_data` → `ingest_farm_data` → `get_collection_status` | 트레이스에 포털 다운로드가 보여야 함. 기상 첫 수신은 약 85MB |
| **C** | 2023-08 완주 기상 + 2024 고추 생육(전국) | `query_collected_data` | 고추에 `sido='전북'` 넣지 말 것. 창고가 비었으면 B를 먼저 |
| **D** | 완주 인근 이상·병해 점검 | `detect_farm_alerts` | 임계값 + 농가 비고. 없는 경보는 만들지 않음 |
| **E** | 토마토 하우스 생육·물 관리 | `query_collected_data` | 토마토는 CSV에 없음. 고추로 바꿔 답하면 안 됨 |

샘플 질문 원문은 `farm_collect_core.SAMPLE_QUESTIONS`에 있습니다.

## 7. 자주 생기는 일

**`data/` 폴더를 지워도 되나**  
됩니다. CSV는 캐시입니다. 시나리오 B에서 다시 받습니다. 설정은 코드에 있으므로 JSON이 필요 없습니다.

**STEP 1에서 CSV가 없다**  
정상입니다. 미리보기는 파일이 있을 때만 나옵니다. 목록은 `COLLECTION_CONFIG`에서 이미 표시됩니다.

**고추 생육이 0건**  
고추는 전국 자료라 `sido`에 전북을 넣으면 안 됩니다. 기상만 완주(`sigungu='완주'`)로 거르세요.

**강수가 수백 mm로 나온다**  
원자료 시간값 합산 특성입니다. 400mm 초과는 경보에서 센서 이상으로 분류합니다.

**기상만 다시 받고 싶다**

```python
download_and_prepare("weather", force=True)
ingest_source("weather")
```

**없는 작물을 다른 작물로 채우지 않기**  
토마토, 딸기, 수박, 참외는 `MISSING_CROPS`로 막아 두었습니다. Agent 시스템 프롬프트도 대체를 금지합니다.

## 8. 이 단원에서 하지 않는 것

- 기상청·농진청 Open API(`serviceKey`) 호출
- 가상 기상·토양 숫자 생성
- 브라우저에서 CSV를 수동 저장한 뒤 그것만 읽기 (감점 대상)

01번 단원(기상청 단기·중기예보 API)과 구분해서 쓰면 됩니다.
