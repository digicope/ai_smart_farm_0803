실습과제: 농업 데이터 수집 자동화 시스템 — 공공 CSV Agent
====================================================================

교과목: 농업 업무 자동화 서비스 개발 실습
단원: 02_농업 데이터 수집 자동화 시스템 개발 실습
권장 파일명: 01_농업_데이터_수집_자동화_에이전트_예제.ipynb


■ 배경
--------------------------------------------------------------------
01번 단원은 기상청 Open API(인증키)를 Agent Tool로 호출했다.

이번 단원은 **Open API 인증키 없이**, 농촌진흥청·공공데이터포털의
**파일데이터(CSV/ZIP)** 를 Agent Tool이 직접 내려받게 한다.

브라우저에서 수동 저장하거나, 미리 받아 둔 파일만 읽는 것이 아니다.
`download_portal_data` Tool이 `fileDownload.do` 로 원문을 받은 뒤
실습용 CSV로 정리하고, 이어서 SQLite 창고에 적재한다.

    사용자: "포털에서 농업 CSV를 내려받고 창고에 적재해줘."
                    │
                    ▼
               AI Agent  (langchain.agents.create_agent)
        ┌───────────┼───────────┬───────────┐
        ▼           ▼           ▼           ▼
  수집대상 목록  포털 다운로드  CSV 적재    조회·경보
  list_data_    download_     ingest_    query /
  sources       portal_data   farm_data  alerts
                    │
                    ▼
         공공데이터포털 파일데이터
         (로그인 없이 CSV/ZIP)
                    │
                    ▼
         data/*.csv (캐시)
                    │
                    ▼
         C:\env\farm_warehouse\farm_warehouse.db


■ 학습 목표
--------------------------------------------------------------------
- Agent Tool이 공공데이터포털 파일 다운로드 URL을 호출하게 한다.
- Open API serviceKey(활용신청 키)는 쓰지 않는다.
  파일데이터 다운로드와 Open API REST를 구분한다.
- 포털 URL·작목·경보 임계값을 코드 상수(COLLECTION_CONFIG)로 둔다.
  별도 collection_config.json 은 쓰지 않는다.
- 받은 CSV를 SQLite 창고에 적재·조회·경보한다.
- CSV에 없는 작물(토마토, 딸기, 수박, 참외)은 지어내거나
  다른 작물로 대체하지 않는다.


■ 사전 준비
--------------------------------------------------------------------
1. C:\env\.env

       OPENAI_API_KEY=OpenAI_API_키

   기상청·농촌진흥청 Open API 키는 사용하지 않는다.
   키 값은 코드/노트북/출력에 노출하지 않는다.

2. 패키지: pandas, requests, python-dotenv,
           langchain, langchain-openai, langchain-core

3. 포털 파일데이터 (사람이 미리 받지 않는다. Tool이 다운로드)

   | Agent source | 내용 | 연도 | 포털 | 정리 파일 |
   |---|---|---|---|---|
   | weather | 완주군 농업기상 일별(반교리·이서면) | 2023 | https://www.data.go.kr/data/15136768/fileData.do | rda_weather_wanju_2023.csv |
   | farm | 노지 농가정보 | 2024 | https://www.data.go.kr/data/15126334/fileData.do | rda_farm_info_2024.csv |
   | growth | 노지 생육. 고추=전국, 밀·배추·양파·콩=전북 | 2024 | 위와 동일 ZIP | rda_growth_2024.csv |
   | pest_sites | 병해충 예찰 지점 | 2015-2024 | https://www.data.go.kr/data/15123424/fileData.do | rda_pest_sites.csv |
   | pest_info | 병해충 목록 | 2025 | https://www.data.go.kr/data/15151253/fileData.do | rda_pest_catalog.csv |

   farm 과 growth 는 같은 ZIP을 받는다.
   기상 원본은 약 85MB이므로, 정리본이 있으면 재다운로드를 생략해도 된다.
   다시 받으려면 download_portal_data(..., force=True).

■ 요구사항 (단계별로 구현할 것)
--------------------------------------------------------------------

[STEP 0] 환경 준비
  - C:\env\.env 에서 OPENAI_API_KEY 만 로드. 키가 없으면 예외.
  - 키 값 출력 금지.
  - ChatOpenAI(model="gpt-4o-mini", temperature=0)
  - 창고 경로: C:\env\farm_warehouse\farm_warehouse.db
  - Agent 생성은 from langchain.agents import create_agent


[STEP 1] 수집 대상 파악
  - COLLECTION_CONFIG (코드 상수)의 source_id, 이름, 파일, 연도,
    제공기관, 포털 URL, 경보 임계값을 표로 남긴다.
  - load_config() 를 사용한다. JSON 파일을 읽지 않는다.
  - 아직 다운로드 전일 수 있다. CSV가 없으면 "아직 없음"만 표시하고
    오류로 멈추지 않는다. 목록 확인 단계이다.


[STEP 2] 포털 파일 다운로드 함수
  - requests 로 공공데이터포털 파일데이터를 받는다.
        상세 페이지 → UDDI
        → selectFileDataDownload.do 로 atchFileId
        → fileDownload.do 로 CSV/ZIP
  - Open API REST(serviceKey, api.odcloud.kr 등)는 쓰지 않는다.
  - ZIP(노지 농가)은 풀어 2024 농가정보·생육 CSV를 만든다.
    farm 또는 growth 어느 쪽을 받아도 농가·생육을 함께 정리한다.
  - 기상은 완주군만 남기고 일별로 집계한다.
    (기온 min/max/mean, 습도, 강수 합)
  - 기상 정리본이 있으면 85MB 원본 재다운로드를 생략한다.
    강제 재수신은 force=True.


[STEP 3] SQLite 창고
  - 테이블: weather, farm, growth, pest_sites, pest_info, ingest_log
  - 날짜 컬럼: weather.obs_date, farm.plant_date,
               growth.survey_date, pest_sites.year
  - 재적재 시 해당 테이블 교체 (if_exists="replace")
  - ingest_log 에 source_id, file_name, row_count, ingested_at 기록


[STEP 4] Tool (6개, LangChain @tool)
  (1) list_data_sources()
      수집 가능 CSV 목록. 목록만 물을 때는 다운로드하지 않는다.

  (2) download_portal_data(source="all", force=False)
      source: weather / farm / growth / pest_sites / pest_info / all
      → 반드시 이 Tool이 포털에서 파일을 받게 한다.
      사람이 미리 받아 둔 CSV만 ingest 하면 감점.

  (3) ingest_farm_data(source="all")
      내려받은 CSV를 SQLite에 적재. 파일이 없으면 download 를 먼저.

  (4) get_collection_status()
      테이블별 건수·기간·적재 시각.

  (5) query_collected_data(table, sido="", sigungu="", crop="",
                           start_date="", end_date="")
      table: weather, farm, growth, pest_sites, pest_info
      전북/완주/김제 등은 sido, sigungu 로 필터.
      병해충명은 table='pest_info', crop 자리에 병명(예: 역병).
      고추 생육은 전국 자료이다. 기상만 완주로 필터한다.
      고추 조회에 sido='전북'을 넣으면 0건이다.

  (6) detect_farm_alerts()
      COLLECTION_CONFIG 임계값 + 농가 비고(병해·폭염).
      임계값:
        humidity_high_pct = 85
        rainfall_heavy_mm = 20
        rainfall_sensor_outlier_mm = 400
        tmax_hot_c = 33
      강수 일합계가 400mm를 넘으면 폭우가 아니라 센서/원자료 이상으로 처리.


[STEP 5] create_agent
  from langchain.agents import create_agent
  - Tool 6개를 장착한다.
  - 시스템 프롬프트에 다음을 넣는다.
      · Open API 인증키(serviceKey)는 쓰지 않는다
      · 내려받아/수집해/포털에서 받아 → download_portal_data 후 ingest
      · 종류만 물으면 → list_data_sources. 다운로드하지 말 것
      · 이상/점검/경보 → detect_farm_alerts 를 반드시 호출
      · 기상은 2023·완주, 농가/생육은 2024
      · 없는 작물(토마토, 딸기, 수박, 참외)은 대체 금지
      · Tool이 돌려준 숫자·날짜·작물만 사용. 없는 값은 추측하지 말 것
      · 고추 생육은 전국. 고추에 sido='전북'을 넣지 말 것
  - 질문 실행은 ask_agent 형태로 답변·호출 Tool·트레이스를 남긴다.


[STEP 6] 실행 시나리오 (A~E 모두 실제 실행)
  질문은 farm_collect_core.SAMPLE_QUESTIONS 와 같다.

  (A) "공공데이터포털에서 받아 자동 수집할 수 있는 농업 데이터 종류를 알려줘."
      → list_data_sources. 다운로드하지 않는 것이 바람직하다.

  (B) "공공데이터포털에서 농업 CSV를 내려받고 창고에 적재한 뒤 수집 현황을 보고해줘."
      → download_portal_data + ingest_farm_data + get_collection_status
      → 도구 호출 트레이스에 포털 다운로드가 보여야 한다.
      → 첫 실행 시 기상 원본 약 85MB 수신이 있을 수 있다.

  (C) "2023년 8월 완주군 농업기상(강수·습도·기온)과 2024년 고추 생육(전국)을 짧게 정리해줘."
      → query_collected_data
      → 기상: 2023-08, sigungu=완주
      → 고추 생육: crop=고추. sido='전북' 을 넣지 말 것
      → 창고가 비었으면 B를 먼저 실행한다.

  (D) "전북 완주 인근 기상과 노지 농가 자료를 기준으로 이상·병해 관련 사항을 점검해줘."
      → detect_farm_alerts 를 반드시 호출
      → 임계값 + 농가 비고. 원자료에 없는 경보는 만들지 않는다.

  (E) "토마토 하우스 생육 데이터와 정식 후 물 관리 기록을 보여줘."
      → 토마토는 CSV에 없다. 고추로 바꿔 답하면 안 된다.
      → 자료 없음을 명시한다.


[STEP 7] 결과 정리
  - 시나리오 A~E에 대해 표를 만든다.
        시나리오 | 기대한 Tool | 실제 호출 Tool | 비고
  - 기대 Tool 예:
        A  list_data_sources
        B  download_portal_data, ingest_farm_data, get_collection_status
        C  query_collected_data
        D  detect_farm_alerts
        E  자료 없음 명시 (토마토를 고추로 대체하지 않음)


■ 구현 조건 / 제약
--------------------------------------------------------------------
- 가상 기상·토양 숫자를 만들지 않는다. 포털 CSV만 사용한다.
- Open API 인증키로 JSON API를 치는 구현은 이 과제 범위가 아니다.
- collection_config.json 을 만들어 읽는 방식은 쓰지 않는다.
  설정은 코드 상수로 둔다.
- data/ 는 캐시다. 폴더가 없어도 STEP 1이 실패하면 안 된다.
- create_agent 사용. (from langchain.agents import create_agent)
- 고추 생육 0건을 피하려면 고추 조회에 전북 필터를 넣지 않는다.
- 강수 일합계가 비정상적으로 크면(400mm 초과) 폭우로 단정하지 않는다.
