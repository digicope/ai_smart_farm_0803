====================================================================
실습과제: 생성형 AI 기반 영농일지 자동 작성 시스템
====================================================================

교과목: 농업 업무 자동화 서비스 개발 실습
단원: 03_생성형 AI 기반 영농일지 자동 작성 시스템 개발 실습
권장 파일명: 생성형AI_영농일지_자동작성_실습_답안.ipynb


■ 배경
--------------------------------------------------------------------
01번 단원은 기상청 API와 작물 길잡이 PDF를 Agent Tool로 연결했다.
02번 단원은 공공데이터포털 CSV를 내려받아 SQLite 창고에 적재했다.

이번 단원은 그 창고 자료를 **근거**로 쓰고, 농가의 구어체 메모를
**구조화된 영농일지**로 바꾸는 생성형 AI 서비스를 만든다.

핵심은 "잘 읽히는 글을 쓰는 것"이 아니다.
숫자·작물·약제·날짜를 지어내지 않고, Tool이 돌려준 값과 메모에
적힌 사실만으로 일지를 채우는 것이다.

    사용자: "어제 고추밭 일 한 거 일지로 남겨줘.
             이슬 많았고 잎에 반점 보여서 약 뿌렸어."
                    │
                    ▼
               AI Agent  (langchain.agents.create_agent)
        ┌───────────┼───────────┬───────────┐
        ▼           ▼           ▼           ▼
  메모 해석     당일 기상     농가·생육     병해충 검색
  parse_      get_diary_   get_crop_    search_pest_
  work_memo   weather      field_       info
                           context
                    │
                    ▼
              LLM 영농일지 초안
              (스키마 고정 JSON)
                    │
                    ▼
         save_farm_diary  →  SQLite 영농일지 테이블
         query_saved_diaries 로 재조회


■ 학습 목표
--------------------------------------------------------------------
- 비정형 영농 메모(구어체)를 날짜·작물·작업·관찰로 분해한다.
- 02번 SQLite 창고의 기상·농가·생육·병해충만 근거로 일지를 채운다.
- 영농일지 항목을 Pydantic(또는 동등한 JSON Schema)으로 고정한다.
- 생성 결과를 창고에 저장하고, 작물·기간으로 다시 조회한다.
- 메모에 없는 약제명·살포량·수확량을 만들지 않는다.
- 창고에 없는 작물(토마토, 딸기, 수박, 참외)은 다른 작물로 대체하지 않는다.


■ 사전 준비
--------------------------------------------------------------------
1. C:\env\.env

       OPENAI_API_KEY=OpenAI_API_키

   기상청·농촌진흥청 Open API 키는 사용하지 않는다.
   키 값은 코드/노트북/출력에 노출하지 않는다.

2. 패키지: pandas, python-dotenv, pydantic,
           langchain, langchain-openai, langchain-core

3. 02번 단원에서 만든 창고를 읽는다.

       C:\env\farm_warehouse\farm_warehouse.db

   테이블 weather, farm, growth, pest_info 가 있어야 한다.
   창고가 비었으면 02 폴더 `data/*.csv` 를 같은 스키마로 적재해도 된다.
   03번에서 공공데이터포털을 다시 받을 필요는 없다.

4. 데이터 연도 (02번과 동일, 섞어 쓰지 말 것)

   | 구분 | 연도 | 범위 | 비고 |
   |---|---|---|---|
   | 농업기상 weather | 2023 | 전북 완주군 반교리·이서면 | 영농일지 기상 근거 |
   | 노지 농가 farm | 2024 | 전국. 완주는 양파 등 | 필지·품종 참고 |
   | 노지 생육 growth | 2024 | 고추=전국, 밀·배추·양파·콩=전북 | 생육 참고 |
   | 병해충 pest_info | 2025 목록 | 병명 검색 | 증상 참고 |

   있는 작목: 고추, 마늘, 밀, 배추, 사과, 양파, 옥수수, 콩, 포도, 논벼
   없는 작목: 토마토, 딸기, 수박, 참외

   실습 메모의 작업일은 **2023년 날짜**를 쓴다.
   그래야 weather 테이블과 같은 날로 대조할 수 있다.
   2024 농가·생육은 "같은 작물의 참고 정보"이며, 일지의 작업일 기상으로
   쓰지 않는다.

■ 영농일지 스키마 (반드시 이 항목을 채울 것)
--------------------------------------------------------------------
일지 1건은 아래 구조를 따른다. 필드명을 바꿔도 의미는 유지한다.

  diary_id          저장 시 부여
  work_date         YYYY-MM-DD (메모에서 추출)
  region            예: 전북 완주군
  crop              작물명
  variety           있으면 농가표, 없으면 빈 값. 추측 금지
  weather           tmin_c, tmax_c, tavg_c, humidity_pct, rainfall_mm,
                    station, source_year
                    → weather 테이블 값만. 없으면 null 및 사유
  work_items        리스트.
                    category: 파종/정식/시비/관수/방제/적심/수확/기타 중 하나
                    description: 메모 근거 한 줄
                    material: 메모에 적힌 자재만. 없으면 ""
                    amount: 메모에 적힌 양만. 없으면 ""
  growth_note       생육 관찰. 메모 + (있으면) growth 요약. 없는 수치 창작 금지
  pest_note         병해충. 메모 증상 + pest_info 검색 결과.
                    검색이 안 되면 "자료에서 특정하지 못함"
  special_note      특이사항. 기상 이상(폭우·고온·다습)은 창고 수치와 연결
  next_plan         다음 작업 제안. 근거 없는 약제 처방은 쓰지 말 것
  evidence          weather_rows, farm_rows, growth_rows, pest_names 사용 여부
  raw_memo          원문 메모 그대로
  narrative_ko      농가가 읽기 쉬운 문장형 일지 1편 (근거 수치 포함)

약제 안전 규칙:
  메모에 상품명·희석배수·살포량이 없으면 work_items.material / amount 를
  비우고, "방제 실시(약제명 미기재)"처럼만 적는다.
  LLM이 임의 농약명(예: 마이신, 스트로빌루린 제품명)을 넣으면 감점이다.


■ 요구사항 (단계별로 구현할 것)
--------------------------------------------------------------------

[STEP 0] 환경 준비
  - C:\env\.env 에서 OPENAI_API_KEY 만 로드. 키가 없으면 예외.
  - 키 값 출력 금지.
  - ChatOpenAI(model="gpt-4o-mini", temperature=0)
  - 창고: C:\env\farm_warehouse\farm_warehouse.db
  - 영농일지 테이블은 같은 DB에 farm_diary 로 만든다.
  - Agent 생성은 from langchain.agents import create_agent


[STEP 1] 창고 연결 확인
  - weather, farm, growth, pest_info 건수와 날짜 범위를 표로 남긴다.
  - 비어 있으면 02 `data/` CSV를 ingest 하는 코드를 실행한 뒤 다시 확인한다.
  - 기상 샘플로 아래 날짜가 조회되는지 확인한다. (시나리오에서 사용)

        2023-08-10  반교리  강수 173mm, 습도 약 93%  (폭우·다습)
        2023-08-15  반교리  최저 24 / 최고 32, 강수 0
        2023-08-18  반교리  강수 20mm

  - 이서면 2023-08-10 강수가 비정상적으로 크면(400mm 초과)
    02번과 같이 폭우로 단정하지 말고 센서/원자료 이상으로 적는다.
    일지 기상은 반교리 값을 우선한다.


[STEP 2] 영농일지 스키마
  - Pydantic BaseModel 로 FarmDiary 를 정의한다.
  - work_items 는 중첩 모델.
  - 수치 필드는 float | None, 문자열 기본값은 "".
  - model_json_schema() 또는 동등한 스키마를 노트북에 출력해 둔다.
  - 이후 저장·검증은 이 모델로만 한다. 자유 텍스트만 저장하면 감점.


[STEP 3] 샘플 메모 (코드 상수)
  - SAMPLE_MEMOS 리스트를 코드에 둔다. 외부 txt에만 의존하지 않는다.
  - 최소 아래 5건을 넣는다. 구어체를 유지한다.

    (A) 관수·시비, 병해 없음
        "2023년 8월 15일 완주 고추밭. 낮에 더워서 물 한번 줬고
         웃거름도 조금 했어. 열매는 달렸는데 갯수는 세지 못함."

    (B) 방제 + 증상만, 약제명 없음  ← 약제 창작 금지 검증
        "8월 18일 완주 고추. 어제부터 비 오고 습해서 잎에 갈색 반점이
         보임. 오후에 약 뿌렸음. 약 이름은 기억 안 남."

    (C) 폭우 다음날 점검
        "2023-08-10 완주. 비가 너무 많이 와서 고추밭 물 빠지나 보고
         고랑 정리만 했음. 수확은 안 함."

    (D) 저장 후 재조회용 (양파, 완주 농가표와 연결)
        "2023년 8월 15일 전북 완주 양파밭은 이미 수확 끝난 뒤라
         잔재 정리만 했어."

    (E) 자료 없음
        "오늘 토마토 하우스 정식하고 점적관수 시작했어.
         일지에 품종이랑 오늘 기온 넣어서 작성해줘."

  - 메모 (A)~(D)의 작업일은 2023-08-10 / 08-15 / 08-18 만 사용한다.


[STEP 4] Tool (6개, LangChain @tool)

  (1) parse_work_memo(memo: str)
      날짜, 지역, 작물, 작업 범주, 자재, 증상, 불명확 항목을 JSON으로.
      LLM 호출을 Tool 안에서 해도 된다.
      작업일이 없으면 work_date="" 로 두고, 오늘 날짜를 임의로 넣지 말 것.
      작물을 단정할 수 없으면 crop="" .

  (2) get_diary_weather(work_date: str, prefer_station="반교리")
      weather 테이블에서 obs_date = work_date, sigungu 완주.
      반교리 행을 우선하고, 이서면은 참고로만 붙인다.
      해당 날짜가 없으면 "창고에 없음"을 반환. 인접 날짜로 대체하지 말 것.
      연도가 2023이 아니면 매핑하지 말고, 2023이 아니라고 명시한다.

  (3) get_crop_field_context(crop: str, sido="", sigungu="")
      farm, growth 요약.
      고추 생육은 전국. sido='전북'을 넣으면 0건이 된다.
      완주 양파 농가는 sigungu에 완주를 넣어도 된다.
      없는 작물이면 빈 결과 + crops_not_in_data 안내.

  (4) search_pest_info(crop: str, symptom: str)
      pest_info 에서 병명·증상 키워드 검색.
      상위 3건만. 원문에 없는 방제 약제는 넣지 않는다.

  (5) save_farm_diary(diary_json: str)
      FarmDiary 검증 후 farm_diary 테이블에 INSERT.
      검증 실패(없는 필드, 타입 오류)면 저장하지 않고 오류 메시지를 반환.
      저장 성공 시 diary_id 를 돌려준다.

  (6) query_saved_diaries(crop="", start_date="", end_date="")
      저장된 일지 목록. 본문 전체가 아니라
      diary_id, work_date, crop, work 요약, 저장시각.


[STEP 5] create_agent
  from langchain.agents import create_agent
  - Tool 6개를 장착한다.
  - 시스템 프롬프트에 다음을 넣는다.
      · 일지 작성 요청 → parse_work_memo 후 weather / field / pest 를
        필요한 만큼 호출하고, FarmDiary JSON을 만든 뒤 save_farm_diary
      · 이미 저장한 일지만 물으면 → query_saved_diaries. 새로 만들지 말 것
      · 기상 숫자는 get_diary_weather 결과만 사용
      · 2024 생육 수치를 2023 작업일 기상처럼 쓰지 말 것
      · 메모에 없는 약제명·살포량·수확량·품종을 채우지 말 것
      · 토마토, 딸기, 수박, 참외는 창고에 없다. 고추로 바꾸지 말 것
      · 작업일이 비었거나 창고에 해당 일 기상이 없으면 그 사실을 일지에 명시
      · next_plan 에 구체 농약 처방(제품명, 희석배수)을 쓰지 말 것
      · API 키를 출력하지 말 것
  - 질문 실행은 ask_agent 형태로 답변·호출 Tool·트레이스를 남긴다.
  - 최종 일지는 narrative_ko 와 JSON(또는 표)을 함께 보여 준다.


[STEP 6] 실행 시나리오 (A~E 모두 실제 실행)
  질문은 SAMPLE_MEMOS 원문을 넣어도 되고, 아래처럼 "일지로 작성해줘"를
  붙여도 된다.

  (A) "다음 메모를 영농일지로 작성하고 저장해줘.
       2023년 8월 15일 완주 고추밭. 낮에 더워서 물 한번 줬고
       웃거름도 조금 했어. 열매는 달렸는데 갯수는 세지 못함."
      → parse_work_memo + get_diary_weather + get_crop_field_context
        + save_farm_diary
      → 기상에 2023-08-15 반교리 최저·최고·강수 0 이 들어가야 한다.
      → 열매 개수를 생육표에서 가져와 단정하지 말 것.
         (메모가 "세지 못함")

  (B) "다음 메모를 영농일지로 작성하고 저장해줘.
       8월 18일 완주 고추. 어제부터 비 오고 습해서 잎에 갈색 반점이
       보임. 오후에 약 뿌렸음. 약 이름은 기억 안 남."
      → search_pest_info 호출
      → work_items 에 방제가 있고 material 은 비어 있거나
        "약제명 미기재"
      → 임의 살균제 상품명이 들어가면 실패

  (C) "2023-08-10 완주. 비가 너무 많이 와서 고추밭 물 빠지나 보고
       고랑 정리만 했음. 수확은 안 함. 일지로 남겨줘."
      → 반교리 강수 173mm, 습도 약 93%를 special_note/weather 에 인용
      → 이서면 2458.5mm 를 실제 폭우 mm로 일지에 쓰지 말 것
      → 수확량 숫자를 만들지 말 것

  (D) "저장한 영농일지 중에서 고추, 2023년 8월 것만 목록으로 보여줘."
      → query_saved_diaries
      → A/B/C 가 저장되어 있어야 한다.
      → 새 일지를 또 생성하지 않는 것이 바람직하다.

  (E) "오늘 토마토 하우스 정식하고 점적관수 시작했어.
       일지에 품종이랑 오늘 기온 넣어서 작성해줘."
      → 토마토는 CSV에 없다. 고추로 바꿔 작성하면 안 된다.
      → "오늘"을 시스템 날짜로 기상 조회해도 weather(2023)와
        맞지 않으면 기온을 지어내지 말고 자료 부족을 명시한다.
      → save_farm_diary 를 강제하지 않는다. 저장했다면
        crop=토마토 + weather null + 부족 사유가 있어야 한다.

--------------------------------------------------------------------
- 가상 기상·수확량·약제 숫자를 만들지 않는다. 창고와 메모만 사용한다.

  창고 2023-08-10/15/18 과 숫자가 일치해야 한다.
  실API "오늘 예보"로 대체하면 감점이다.
