====================================================================
실습과제: AI Agent 기반 농업 정보 검색 서비스
====================================================================

교과목: 농업 업무 자동화 서비스 개발 실습
단원: 04_AI Agent 기반 농업 정보 검색 서비스 개발 실습
권장 파일명: AI_Agent_기반_농업_정보_검색_실습_답안.ipynb


■ 배경
--------------------------------------------------------------------
01번 단원은 기상청 예보 API와 작물 길잡이 PDF를 Agent Tool로 연결했다.
02번 단원은 공공데이터포털 CSV를 내려받아 SQLite 창고에 적재했다.
03번 단원은 그 창고를 근거로 영농일지를 자동 작성했다.

이번 단원은 **외부 Open API를 쓰지 않는다.**
같은 폴더의 **농업기술길잡이 PDF** 와 **압축 CSV 2종** 을 로컬 Tool로 연결하고,
최신 이슈만 **API 키가 필요 없는 웹 검색**으로 보강한다.

사용자가 자연어로 물으면 Agent가 질문 의도를 판단하고,
필요한 도구만 골라 재배 지식(PDF) · 실측 데이터(CSV) · 최신 정보(웹)를
섞어 **농업 정보 답변**을 만든다.

목표 흐름은 다음과 같다.

                 AI 농업 Agent
                      │
       ┌──────────────┼──────────────┐
       ↓              ↓              ↓
   농업기술 RAG    농업 CSV        웹 검색
       │              │              │
       ↓              ↓              ↓
   PDF 자료      실제 데이터     최신 정보
       └──────────────┼──────────────┘
                      ↓
                    LLM
                      ↓
              농업 정보 답변

핵심은 세 갈래를 매번 전부 치는 것이 아니다.
질문 의도에 맞는 Tool만 호출하고, Tool이 돌려준 근거만으로 답하는 것이다.
PDF에 없는 재배법, CSV에 없는 작물·수치, 웹에 없는 뉴스는 지어내지 않는다.


■ 학습 목표
--------------------------------------------------------------------
- 농업기술길잡이 PDF를 청킹·임베딩해 RAG 검색 Tool로 연결한다.
- 노지 ZIP · 스마트팜 ZIP을 풀어 CSV를 읽고, 요약 통계 Tool로 감싼다.
- API 키가 필요 없는 웹 검색 Tool로 최신 농업 이슈를 보강한다.
- 질문 의도(재배지식 / 실측데이터 / 최신정보 / 종합)에 따라
  적절한 Tool만(또는 필요한 조합만) 선택하게 한다.
- CSV 원문 전체와 환경 데이터 수십만 행을 LLM에 넣지 않는다.
- 근거가 없는 작물·기간·수치는 "주어진 자료만으로는 알 수 없다"고 답한다.


■ 사전 준비
--------------------------------------------------------------------
1. C:\env\.env 에서 OpenAI 키만 사용한다.

       OPENAI_API_KEY=OpenAI_API_키

   기상청 키, 농업기술 데이터 플랫폼 키, Tavily/Serper/Google/Bing 검색 키는
   사용하지 않는다. 다른 API를 호출하면 감점이다.
   키 값은 코드/노트북/출력에 노출하지 않는다.

2. 권장 패키지:
       pandas, python-dotenv, pypdf, openpyxl,
       langchain, langchain-openai, langchain-core, langchain-community,
       langgraph, faiss-cpu, ddgs
       (ddgs 가 없으면 duckduckgo-search 도 가능)

3. 압축 파일은 같은 폴더에서 직접 풀어 사용한다.
   공공데이터포털·농업기술 데이터 플랫폼을 다시 호출할 필요는 없다.

■ 요구사항 (단계별로 구현할 것)
--------------------------------------------------------------------

[STEP 0] 환경 준비
  - C:\env\.env 에서 OPENAI_API_KEY 만 로드한다.
  - 키가 없으면 예외를 발생시키고, 키 값은 출력하지 않는다.
  - LLM은 예: ChatOpenAI(model="gpt-4o-mini", temperature=0)
  - 임베딩은 예: OpenAIEmbeddings(model="text-embedding-3-small")
  - Agent 생성은 from langchain.agents import create_agent
  - 압축 해제 위치 예: 같은 폴더 data/  (노지_2024/, 스마트팜_2024/)
  - 벡터스토어 persist 예: C:\env\agri_search_faiss


[STEP 1] 자료 해제와 목록 파악
  - 노지_2024.zip, 스마트팜_2024.zip 을 풀어 파일 목록을 표로 남긴다.
  - 노트북에 다음을 정리한다.

        구분 | 파일 | 행 수 | 주요 컬럼 | 작물 | 기간 힌트

  - CSV는 CP949(또는 utf-8-sig)로 읽는다. 인코딩 오류를 처리한다.
  - 환경 CSV 2개는 전체 head만 확인하고, 전 행을 display 하지 않는다.
  - 컬럼명 불일치에 대비한다.
        예: 환경 파일마다 '잔존 CO2' / '잔존CO2'
            수박 생육은 '도명' 컬럼 (다른 작물은 '도')
            노지 사과 생육은 utf-8-sig, 나머지 노지 CSV는 CP949일 수 있다.
  - 이 단계에서 키 값, CSV 원문 전체를 붙여 넣지 않는다.
    컬럼 목록과 샘플 1~2행만 보여 준다.


[STEP 2] 농업기술 RAG Tool (PDF)
  - [A]의 PDF 7종을 모두 로드한다.
  - 청크 메타데이터에 최소 다음을 넣는다.
        crop (토마토/고추/수박/참외/고구마/딸기/사과),
        source (파일명), page
  - 파일명으로 crop 을 매핑한다.
  - RecursiveCharacterTextSplitter 등으로 청킹한다.
    (권장: chunk_size 800~1000, overlap 100~150)
  - 벡터스토어를 만들고 persist 한다. (재실행 시 재임베딩하지 않기)
  - LangChain `@tool` 로 감싼다. 예:
        search_crop_guide(query: str, crop: str = "")
    crop 이 주어지면 해당 작물 청크만 검색한다.
  - 검색 결과에는 작물명, 파일명, 페이지, 발췌문을 포함한다.
  - 검색된 문맥에 없는 내용은 만들지 않도록 description/프롬프트를 적는다.


[STEP 3] 농업 CSV Tool (로컬 실측)
  - ZIP에서 푼 CSV/XLSX만 읽는다. 포털·Open API를 다시 치지 않는다.
  - 최소 아래 2개를 `@tool` 로 만든다. (더 쪼개도 된다)

    (1) query_field_csv(crop: str, kind: str, region: str = "")
        kind: "farm" | "growth"
        노지_2024 농가정보·생육기본.
        건수, 지역, 평균 초장/착과/수확량 등
        (실제 컬럼에 있는 항목만) 요약 문자열로 반환.

    (2) query_smartfarm_csv(crop: str, kind: str,
                            region: str = "",
                            start_date: str = "", end_date: str = "")
        kind: "cultivation" | "environment" | "growth" | "production"
        스마트팜 재배정보·환경·생육·생산.
        환경은 반드시 품목(필요하면 기간·지역)으로 필터한 뒤
        내부온도·습도·CO2 등의 평균·최소·최대·건수만 반환.
        원본 수십만 행을 그대로 반환하면 감점.

  - "토마토" 요청 시 스마트팜에서는 완숙토마토와 방울토마토를
    구분해 조회하거나, 둘 다 조회했음을 명시한다.
  - 해당 작물/kind 파일이 없으면 "자료 없음"을 반환한다.
    예: query_field_csv("딸기", "growth") → 노지에 딸기 없음
    예: query_smartfarm_csv("사과", "environment") → 스마트팜에 사과 없음
  - 없는 수확량·온습도 숫자를 만들지 말 것.


[STEP 4] 웹 검색 Tool (최신 정보)
  - LangChain `@tool` 로 감싼다. 예:
        search_web(query: str)
  - DuckDuckGo(ddgs) 등 API 키가 필요 없는 방식만 사용한다.
  - Tavily, Serper, Google Custom Search, Bing, 네이버 검색 API,
    기상청 Open API, 농업기술 데이터 플랫폼 Open API 는 금지.
  - 상위 3~5건의 제목, URL, 짧은 발췌를 반환한다.
  - 검색 실패·0건이면 "검색 결과 없음"을 반환한다. 뉴스를 지어내지 말 것.
  - Tool description에 다음을 적는다.
        재배 매뉴얼은 PDF, 실측 숫자는 CSV를 쓰고
        웹 검색은 올해 이슈·정책·시세·병해충 경보 등 최신 정보에만 쓴다.


[STEP 5] Agent 구성
  - 위 Tool(RAG + CSV + 웹)을 장착한 Agent를 만든다.
    from langchain.agents import create_agent
  - 시스템 프롬프트에 다음을 분명히 넣는다.

      · 정식/육묘/시비/병해충 방제 등 재배 지식 → search_crop_guide
      · 2024 노지 농가·생육 숫자 → query_field_csv
      · 스마트팜 온실 환경·생육·출하량 → query_smartfarm_csv
      · 올해/최근/시세/발생 소식 등 최신 정보 → search_web
      · 종합 질문이면 필요한 Tool만 조합. 무관한 Tool은 호출하지 말 것
      · 숫자는 CSV Tool 결과만 사용. 웹 스니펫 숫자로 대체하지 말 것
      · 재배법은 PDF 발췌만 사용. PDF에 없으면 웹으로 매뉴얼을 대체하지 말 것
      · 자료에 없는 작물은 다른 작물로 바꿔 답하지 말 것
      · 답에 근거를 인용한다 (PDF: 파일명·페이지 / CSV: 작물·건수·기간 /
        웹: 제목·URL)
      · API 키를 사용자에게 출력하지 말 것

  - 질문 실행은 ask_agent 형태로
    답변 · 호출 Tool · 트레이스를 노트북에 남긴다.


[STEP 6] 실행 시나리오 (최소 5개, 모두 실제 실행)
  아래 질문을 같은 Agent로 실행하고, 호출된 Tool 목록과 최종 답을 남긴다.

  (A) PDF만
      "고구마 정식과 물 관리 요령을 농업기술길잡이 기준으로 요약해줘."
      → search_crop_guide 만 호출하는 것이 바람직하다.
      → CSV·웹을 치지 않아야 한다.
      → 답에 파일명·페이지 근거가 있어야 한다.

  (B) 노지 CSV만
      "2024년 노지 고추 생육을 요약해줘. 초장이나 착과가 어느 정도인지
       지역별로 알려줘."
      → query_field_csv(crop="고추", kind="growth")
      → 스마트팜 토마토 숫자로 고추를 대체하면 안 된다.
      → 답에 실제 건수·평균(또는 범위)이 있어야 한다.

  (C) 스마트팜 CSV만
      "스마트팜 완숙토마토 내부 온습도가 어떤지, 출하량도 같이 요약해줘."
      → query_smartfarm_csv 의 environment 와 production
        (생육이 필요하면 growth 추가)
      → 환경 원문 전체를 출력하지 말 것.
      → 노지 2024 고추 숫자로 대체하면 안 된다.

  (D) RAG + CSV + 웹  (핵심 시나리오)
      "딸기 재배 주의사항을 길잡이에서 찾고,
       스마트팜 딸기 생육·환경 숫자와 최근 딸기 관련 이슈를 함께 정리해줘."
      → search_crop_guide + query_smartfarm_csv + search_web 이
        모두 사용되어야 한다.
      → 답변에 PDF 근거(파일명·페이지), CSV 수치(건수·평균 등),
        웹 제목·URL 이 함께 들어가야 한다.
      → 세 결과를 단순 나열하지 말고, 재배 요령과 실측·최신 이슈가
        어떻게 연결되는지 한 단락으로 해석한다.
        (단, Tool에 없는 인과는 단정하지 말 것)

  (E) 자료 없음 / 잘못된 라우팅 방지
      "벼 논물 수심이 적절한지, 2024년 노지 딸기 생육 초장과
       스마트팜 사과 내부온도까지 알려줘."
      → 벼는 PDF·CSV에 없다.
      → 딸기는 스마트팜·PDF에만 있고 노지 CSV에 없다.
      → 스마트팜에 사과가 없다. (사과는 PDF·노지 CSV에 있음)
      → 고추·토마토·노지 사과 숫자로 벼/노지 딸기/스마트팜 사과를
        대신 답하면 안 된다.
      → 없는 수심·초장·내부온도를 만들어 내지 말 것.


[STEP 7] 결과 정리
  - 시나리오 A~E에 대해 표를 만든다.

        시나리오 | 질문 의도 | 기대한 Tool | 실제 호출 Tool | PDF 근거 | CSV 근거 | 웹 근거 | 비고

  - 기대 Tool 예:
        A  search_crop_guide
        B  query_field_csv
        C  query_smartfarm_csv (environment, production)
        D  search_crop_guide, query_smartfarm_csv, search_web
        E  자료 없음 명시 (다른 작물로 대체하지 않음)

  - (D)의 최종 자연어 답변 전문을 노트북에 남긴다.
  - 답변은 농가가 읽을 수 있는 문장이어야 한다.
    JSON 원문만 출력하고 끝내지 말 것.


■ 구현 조건 / 제약
--------------------------------------------------------------------
- OPENAI_API_KEY 이외의 API 키·엔드포인트를 사용하지 않는다.
  (기상청, 농업기술 데이터 플랫폼, Tavily, Serper, Google, Bing 금지)
- 가상 온습도·생육·수확량·뉴스 제목을 만들지 않는다.
- 환경 CSV 전체(약 20MB + 56MB)를 LLM 컨텍스트에 넣지 않는다.
- PDF 답변은 검색된 청크에만 근거한다.
- 웹 검색 결과는 최신 이슈 보강용이다. 재배 매뉴얼이나 CSV 숫자를
  웹으로 대체하면 감점이다.
- 질문 의도와 무관한 Tool을 습관적으로 3개 전부 치면 감점이다.
  (시나리오 D만 RAG+CSV+웹을 모두 사용)
- 01~03번 노트북을 그대로 제출하면 안 된다.
  본 폴더 PDF 7종과 ZIP 2개가 포함되어야 한다.
- create_agent 사용. (from langchain.agents import create_agent)
- Windows에서 Chroma persist 한글 경로 문제가 있으면 FAISS 등 대안을 사용한다.
- ZIP 엔트리 한글 이름이 깨지면 CP949로 풀어 data/ 에 저장한 뒤 읽는다.
